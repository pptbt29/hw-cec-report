# KV Manager 对跨节点推理的系统作用：配对模拟分析

## 结论

**KV Manager 的主要作用不是单独减少某一项传输时延，而是降低跨节点执行所需支付的状态恢复门槛，使 Router 能在更小的节点排队差下使用空闲节点。** 这一变化扩大了可行路由范围，进而改善后续队列分布。

在 Qwen2-VL-7B、并发 session 数为 24 的实验中，保持请求轨迹和单请求穷举 Router 完全相同，仅开启 KV Manager 后：

- 已选择恢复动作的状态恢复时延 P50 从 **112.0 ms** 降至 **42.1 ms**，下降 **62.4%**；
- 触发跨节点状态恢复所对应的节点排队差 P50 从 **210.4 ms** 降至 **136.9 ms**；
- 每次运行选择的状态恢复动作由 **24.2 次**增至 **51.8 次**，说明更多低负载节点进入可用范围；
- 全部请求的平均排队时延从 **22.7 ms** 降至 **9.6 ms**；
- 平均 TTFT 下降 **6.5%**，平均 E2E 下降 **4.4%**。
- SLA 违约率从 **3.57%** 降至 **1.00%**；同一压力下就近执行的违约率为 **10.41%**。

KV Manager 的增量收益随系统压力增加：并发数从 8 增至 48 时，相对同一 Router 被动恢复配置的平均 TTFT 收益由 **1.5%** 增至 **10.5%**，平均 E2E 收益由 **1.0%** 增至 **7.7%**。这说明 KV Manager 在节点间存在明显队列差、但状态恢复仍会阻碍负载均衡时价值最大。

进一步的能力分级实验表明，KV Manager 不能仅靠“多复制 KV”得到稳定收益。并发 24 时，仅启用块级残余恢复可降低 E2E **1.7%**；仅主动预放置但仍按完整状态恢复，E2E 反而上升 **0.5%**。二者结合后，弱、当前和强配置分别降低 E2E **2.6%**、**4.4%** 和 **6.0%**。因此，块级可复用性是主动预放置能够转化为在线收益的必要接口。

**KV Manager 本身并不产生全部 20% 收益。** 在并发 24 时，“单请求穷举 + KV Manager”相对就近执行的平均 E2E 总收益为 **19.3%**，其中 KV Manager 在单请求穷举 Router 之上提供 4.4% 的增量；并发 36 时，总收益达到 **23.7%**，KV Manager 的增量为 6.8%。因此，完整收益来自“当前请求的节点选择”和“状态准备能力”共同作用。

## 1. 实验要回答的问题

实验检验以下因果链是否成立：

1. 后台预放置和块级残余恢复降低单次状态恢复成本；
2. 恢复成本降低后，Router 不必等待完整 KV 所在节点出现很大的排队积压，便可选择其他节点；
3. 更多请求可以利用低负载节点，后续队列分布得到改善；
4. 排队和状态准备关键路径的变化最终降低 TTFT 和 E2E。

为隔离 KV Manager 的作用，每个随机种子只生成一次请求轨迹，并在同一轨迹上运行以下两种配置：

| 配置 | Router | KV 状态处理 |
|---|---|---|
| KV Manager 关闭 | 枚举当前请求的全部可行节点与 KV 获取方式，选择预计 E2E 最小的动作 | 无后台预放置；按完整状态进行被动恢复 |
| KV Manager 开启 | 与关闭配置完全相同 | 后台增量预放置；请求到达后只恢复缺失的连续 KV blocks |

就近执行仅用于表示完整方案的总收益，不参与 KV Manager 开关的因果归因。

### 实验配置

| 项目 | 设置 |
|---|---|
| 模型 | Qwen2-VL-7B-Instruct |
| 集群 | 3 个 A800T-A2 推理节点；链路 100/100/25 Gbps |

| 单轮输入 | 截断对数正态分布，均值/标准差均为 256 text tokens，范围 $[8,2048]$；另含 4 帧 $1024\times768$ 图像 |

| 并发 session 数 | 8、16、24、36、48 |

系统级指标先在每次运行内对全部请求求均值，再对 5 个随机种子进行配对统计。状态恢复事件的分布由同一并发配置下的事件合并得到，仅用于解释机制，不将事件数当作独立实验次数。实验直接读取生成轨迹中的真实剩余请求数，排除 session continuation 预测误差；目标节点仍按 Markov 入口转移概率选择，而非读取真实未来入口。

## 2. KV Manager 为什么会改变路由边界

设节点 $o$ 持有当前请求的完整最新 KV，节点 $j$ 缺少部分 KV，但排队更短。在两个节点执行的预计成本分别为

$$
C_o=Q_o+C_o^{\mathrm{other}},
$$

$$
C_j=Q_j+R_j+C_j^{\mathrm{other}},
$$

其中 $Q$ 为排队时延，$R_j$ 为节点 $j$ 的状态恢复时延，$C^{\mathrm{other}}$ 包含请求通信、Prefill、Decode 和结果返回等其余成本。Router 选择节点 $j$ 的条件为

$$
Q_o-Q_j
>
R_j+\left(C_j^{\mathrm{other}}-C_o^{\mathrm{other}}\right).
$$

当前实验使用同构推理节点，两个候选动作的其余成本通常接近，因此决策边界近似为

$$
\Delta Q_j>R_j,
\qquad
\Delta Q_j=Q_o-Q_j.
$$

KV Manager 通过后台预放置连续 prefix，并在请求到达时只同步或重算残余 blocks，从而降低 $R_j$。因此，跨节点执行所需的最小排队差也随之下降。

## 3. 并发 24：从恢复成本到系统收益的完整证据链

### 3.1 状态恢复门槛

下表统计 Router 实际选择了迁移或重算的请求。关闭和开启 KV Manager 时分别包含 121 和 259 个事件，即每次运行平均 24.2 和 51.8 个事件。

| 指标 | KV Manager 关闭 | KV Manager 开启 | 变化 |
|---|---:|---:|---:|
| 恢复时延均值 | 125.4 ms | 53.1 ms | -57.7% |
| 恢复时延 P50 | 112.0 ms | 42.1 ms | -62.4% |
| 完整-KV节点与目标节点排队差均值 | 224.0 ms | 153.1 ms | -31.6% |
| 排队差 P50 | 210.4 ms | 136.9 ms | -34.9% |
| 每次运行的恢复动作数 | 24.2 | 51.8 | +114.0% |

恢复动作增加不是额外负担失控，而是更多请求在较小队列失衡时已经满足跨节点执行条件。分布变化进一步说明了这一点：

| 已选择恢复动作对应的排队差 | KV Manager 关闭 | KV Manager 开启 |
|---|---:|---:|
| 小于 150 ms | 32.2% | 56.8% |
| 不低于 300 ms | 27.3% | 6.2% |

关闭 KV Manager 时，Router 往往需要等待完整 KV 所在节点比目标节点多排队 200--300 ms，才足以摊销完整状态恢复。开启后，超过一半的恢复动作已经发生在 150 ms 以下的排队差区间，路由边界明显左移。

### 3.2 全部请求的系统结果

| 指标 | KV Manager 关闭 | KV Manager 开启 | 配对变化 |
|---|---:|---:|---:|
| 平均排队时延 | 22.7 ms | 9.6 ms | -13.1 ms |
| 状态恢复对每请求平均 TTFT 的贡献 | 8.3 ms | 7.6 ms | -0.7 ms |
| 平均 TTFT | 209.6 ms | 195.8 ms | **-6.5%** |
| 平均 E2E | 310.8 ms | 297.0 ms | **-4.4%** |

这里需要区分两个统计口径：

- “恢复时延 P50 从 112.0 ms 降至 42.1 ms”只统计实际发生状态恢复的请求，用于观察单次恢复门槛；
- “状态恢复对每请求平均 TTFT 的贡献从 8.3 ms 降至 7.6 ms”将未发生恢复的请求按 0 计入，用于分解全部请求的平均 TTFT，同时受到恢复次数增加的影响。

因此，KV Manager 的系统价值不能只用摊到全部请求上的状态恢复时延贡献衡量。它首先降低**每个候选恢复动作的成本**，允许 Router 更频繁地利用空闲节点；主要系统收益随后表现为平均排队时延下降 13.1 ms。TTFT 降幅大于 E2E，是因为 Decode 时长基本不受这两项机制影响，会稀释完整 E2E 的相对改善。

## 5. KV Manager 做到不同程度时的系统影响

### 5.1 能力维度与实验等级

KV Manager 的能力由两个相互关联但不等价的维度构成：

- **后台准备能力**：请求到达前能够向候选节点放置多少连续 KV prefix，受复制比例和后台带宽限制；
- **在线残余恢复能力**：请求到达后能否只处理缺失 blocks，以及同步、重算和恢复编排能够将残余时延降到什么程度。

当前后台复制比例为

$$
\alpha_{k,j}
=
\min\left\{
\alpha_0 p_{k,j}\eta_k,
\alpha_{\max}
\right\},
$$

其中 $p_{k,j}$ 是下一请求到达节点 $j$ 的概率，$\eta_k$ 是 session 剩余活跃度，$\alpha_0$ 是基础复制系数，$\alpha_{\max}$ 是单轮复制上限。实验通过改变 $\alpha_0$、$\alpha_{\max}$ 和后台带宽比例构造不同准备能力，并单独控制块级残余恢复。

| 等级 | 主动预放置 | 块级残余恢复 | 基础复制系数 | 单轮复制上限 | 后台带宽上限 | 含义 |
|---|---|---|---:|---:|---:|---|
| 关闭 | 否 | 否 | 0 | 0 | 0 | 完整状态被动恢复 |
| 仅块级恢复 | 否 | 是 | 0 | 0 | 0 | 只利用目标节点已有的连续 prefix |
| 仅主动预放置 | 是 | 否 | 2 | 50% | 20% | 提前复制，但在线仍按完整状态恢复 |
| 弱 | 是 | 是 | 1 | 25% | 5% | 保守的后台准备 |
| 当前 | 是 | 是 | 2 | 50% | 20% | 当前模拟默认配置 |
| 强 | 是 | 是 | 4 | 100% | 50% | 更积极地准备完整缺失 prefix |
| 理想上界 | 是 | 是 | 4 | 100% | 50% | 在强配置基础上令残余恢复时延为 0 |

所有等级使用相同单请求穷举 Router，并在每个 `(并发数, 随机种子)` 上重放完全相同的请求轨迹。

### 5.2 组件消融与能力分级结果

并发 24 下的结果如下。收益均相对“关闭”配置按 seed 配对计算；后台复制量为每次 120 s 运行的平均完成量。

| KV Manager 等级 | 平均 E2E | E2E 收益 | 平均 TTFT | TTFT 收益 | SLA 违约率 | 平均排队 | 后台复制量 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 关闭 | 310.8 ms | -- | 209.6 ms | -- | 3.57% | 22.7 ms | 0 |
| 仅块级恢复 | 305.5 ms | 1.69% | 204.2 ms | 2.51% | 2.97% | 17.6 ms | 0 |
| 仅主动预放置 | 312.4 ms | -0.51% | 211.1 ms | -0.76% | 4.47% | 25.3 ms | 111.0 GB |
| 弱 | 302.6 ms | 2.62% | 201.3 ms | 3.88% | 2.27% | 13.9 ms | 53.2 GB |
| 当前 | 297.0 ms | 4.39% | 195.8 ms | 6.52% | 1.00% | 9.6 ms | 104.3 GB |
| 强 | 292.2 ms | 5.95% | 190.9 ms | 8.83% | 0.56% | 6.4 ms | 136.3 GB |
| 理想上界 | 284.0 ms | 8.58% | 182.8 ms | 12.72% | 0.28% | 4.4 ms | 124.2 GB$^{\dagger}$ |

$^{\dagger}$理想上界改变了请求选择和后续 KV 分布，因此其后台复制量不能与强配置作逐字节的直接比较；该等级只用于表示零残余恢复时延下的性能上界。

组件消融得到以下结论：

1. **块级残余恢复本身有效。** 即使没有后台复制，仅避免重复传输目标节点已经拥有的 blocks，也使平均 E2E 下降 1.69%、TTFT 下降 2.51%。
2. **主动预放置本身不构成充分条件。** 当在线恢复仍按完整 KV 计费时，提前复制的部分 prefix 大多不能抵扣恢复成本；该配置在并发 24 下使 E2E 上升 0.51%，说明“复制更多”不等于“在线状态准备更快”。
3. **两项能力存在明显互补。** 弱配置已经优于仅块级恢复；当前和强配置继续降低排队、TTFT、E2E 和 SLA 违约率。主动放置的部分 blocks 只有通过块级目录和残余恢复接口，才能直接减少请求关键路径上的 $R_j$。

对于 Router 已实际选择的状态恢复动作，其事件加权平均恢复时延由关闭时的 125.4 ms，依次降至仅块级恢复的 88.6 ms、当前配置的 53.1 ms 和强配置的 39.1 ms；理想上界为 0。由于不同等级会选择不同请求，该统计仅用于解释恢复门槛，不用于直接计算系统收益。

### 5.3 压力与能力等级的共同影响

各等级相对关闭配置的 E2E 收益如下。

| 并发 session | 弱 | 当前 | 强 | 理想上界 |
|---:|---:|---:|---:|---:|
| 16 | 1.60% | 2.73% | 3.84% | 5.88% |
| 24 | 2.62% | 4.39% | 5.95% | 8.58% |
| 36 | 4.75% | 6.50% | 8.88% | 12.18% |

各等级相对关闭配置的 TTFT 收益如下。

| 并发 session | 弱 | 当前 | 强 | 理想上界 |
|---:|---:|---:|---:|---:|
| 16 | 2.44% | 4.15% | 5.86% | 8.96% |
| 24 | 3.88% | 6.52% | 8.83% | 12.72% |
| 36 | 6.79% | 9.32% | 12.74% | 17.51% |

在三个压力点上，提高 KV Manager 能力均扩大了系统收益，且高压力下收益更明显。原因不是恢复优化随压力改变，而是高压力时存在更多可被状态恢复能力释放的节点间排队差。并发 24 时，从当前升级到强配置额外降低 E2E 约 1.6%、TTFT 约 2.5%，但后台复制量由 104.3 GB 增至 136.3 GB；继续达到零残余恢复上界，还存在约 2.8% E2E 和 4.3% TTFT 的空间。

因此，KV Manager 的工程目标不应写成“尽可能多地复制 KV”，而应同时关注：

- 单位后台字节带来的残余恢复时延下降；
- 被新增可行节点消除的排队时延；
- 由额外副本占用引起的带宽和存储压力；
- 系统是否已经进入收益趋缓区间。

## 6. KV Manager 的资源代价

主动预放置不是免费操作。并发 24 时，每次 120 s 运行平均完成约 **104.3 GB** 的后台 KV 复制，折合全系统平均约 **0.87 GB/s**。这些流量不进入当前请求的关键路径，但仍消耗链路带宽和目标节点 KV 容量。

因此，当前结果证明的是：在预留后台带宽和容量的条件下，KV Manager 可以用额外状态副本换取更低的恢复门槛和更均衡的队列。多 session 竞争下的带宽分配、副本淘汰和单位资源收益仍需单独评估，不能把后台复制视为零成本。

## 7. 最终判断

KV Manager 对当前系统具有明确但有边界的价值：

- **直接效果**：将已选择恢复动作的 P50 恢复时延降低 62.4%；
- **决策效果**：将恢复动作对应的 P50 排队差从 210.4 ms 降至 136.9 ms，使更多低负载节点可被选中；
- **队列效果**：并发 24 时将全部请求的平均排队从 22.7 ms 降至 9.6 ms；
- **用户效果**：在相同 Router 上额外降低 TTFT 6.5%、E2E 4.4%，并且该增量随系统压力上升；
- **能力上限**：并发 24 时，强配置的 TTFT/E2E 收益达到 8.8%/6.0%，零残余恢复上界达到 12.7%/8.6%；
- **系统代价**：需要后台带宽和 KV 存储，当前并发 24 的复制量约为 104.3 GB/120 s。

因此，KV Manager 不是长期路由的替代品，也不是固定产生 20% 收益的独立优化。它解决的是长期或跨节点路由的前置条件：**把原本占主导地位的状态恢复成本降到能够与排队、通信等成本比较的区间，使 Router 真正拥有多个可竞争的执行节点。**

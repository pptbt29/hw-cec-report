# KV 状态恢复与 session 长期路由的成本区间

## 1. 核心结论

> **只有当一次 KV 恢复成本高于当前请求能够获得的收益、但低于 session 后续请求的累计收益时，长期路由才会做出不同于单请求穷举的选择。**

- KV 恢复成本过高：整个 session 都无法摊销，应继续在持有完整 KV 的节点执行。
- KV 恢复成本很低：当前请求即可摊销，单请求穷举会直接切换节点。
- KV 恢复成本处于两者之间：当前请求不值得切换，但未来多轮可以摊销，此时才需要长期路由。

KV Manager 的作用是降低状态恢复门槛，使更多请求从“整个 session 无法摊销”进入可切换区间。它并不保证长期判断区间持续扩大：恢复成本进一步下降后，请求会进入“当前即可切换”区间。

## 2. 问题背景与系统建模

### 2.1 问题背景

一个 session 由多个先后到达的请求组成。第 $k$ 个请求从入口节点 $U_k$ 接入时，完整 KV prefix 可能仍保存在历史执行节点，而各节点的排队、算力、显存和链路状态也在动态变化。系统可以把小体量请求发送到已有 KV 的节点，也可以在其他节点恢复缺失 KV 后执行。前者需要在后续各轮重复承担转发和排队差异，后者需要支付一次状态恢复成本。

当前请求的执行位置还决定本轮新增 KV 在哪里增长，因此一次路由动作会改变后续请求可见的 KV 分布。实际 session 请求总数 $K$ 在线未知，Router 需要在当前服务成本和未来状态本地性之间进行权衡。

### 2.2 系统状态

第 $k$ 个请求到达时的状态写为：

$$
s_k=
\left(
U_k,x_k,\mathcal C_k,
\mathbf L_k,\mathbf M_k,\mathbf W_k
\right),
$$

其中：

- $U_k$ 和 $x_k$ 分别表示当前入口以及输入长度、预计输出长度和 session 持续性等请求特征；
- $\mathcal C_k$ 记录各节点持有的版本化连续 KV blocks；
- $\mathbf L_k$、$\mathbf M_k$ 和 $\mathbf W_k$ 分别表示节点负载、可用显存和链路状态。

### 2.3 Router 决策变量

Router 对每个请求选择：

$$
a_k=(J_k,Z_k),
\qquad
Z_k\in\{\mathrm{reuse},\mathrm{sync},\mathrm{recompute}\},
$$

其中 $J_k$ 是执行节点，$Z_k$ 是该节点获得所需 KV 的方式：已有完整连续 prefix 时直接复用，否则同步或重建缺失部分。只有满足节点可用性、KV 版本一致性、显存容量和请求 SLA 的动作才进入可行集合 $\mathcal A_k^F(s_k)$。

当目标节点缺少历史 KV 时，模拟器分别估计同步缺失 blocks 和重算缺失 suffix 的时延，并将较快者作为该节点的状态恢复成本；第 5.4 节进一步给出只允许 recompute 时的反事实实验。

给定动作 $a_k$，请求端到端时延分解为：

$$
T_k^{\mathrm{E2E}}(a_k)
=T_k^{\mathrm{comm}}
+T_k^{\mathrm{queue}}
+T_k^{\mathrm{state}}
+T_k^{\mathrm{prefill}}
+T_k^{\mathrm{decode}}
+T_k^{\mathrm{return}}.
$$

其中 $T_k^{\mathrm{state}}$ 是 reuse、sync 或 recompute 对应的状态准备时延。单请求穷举只选择当前 $T_k^{\mathrm{E2E}}$ 最小的动作；长期 Router 的目标是在 session 请求数未知的情况下最小化累计端到端时延：

$$
\pi^*
=\arg\min_{\pi}
\mathbb E_{\pi}
\left[
\sum_{k=1}^{K}T_k^{\mathrm{E2E}}(a_k)
\right],
\qquad
a_k=\pi(s_k)\in\mathcal A_k^F(s_k).
$$

### 2.4 KV Manager 的后台控制量

KV Manager 在请求完成后，将候选节点缺失的连续 KV blocks 作为低优先级后台任务提前复制。对候选节点 $j$，实际放置量为：

$$
D_{k,j}^{\mathrm{place}}
=\min\left\{
\alpha_0p_{U_kj}\eta_kD_{k,j}^{\mathrm{missing}},
B_{k,j}^{\mathrm{bg}}\Delta t_k,
M_{k,j}^{\mathrm{free}}
\right\},
$$

其中 $p_{U_kj}$ 是未来入口转移概率，$\eta_k$ 是 session continuation predictor 给出的剩余活跃度，$\alpha_0$ 是放置强度，后两项分别限制节点 $j$ 当前可获得的后台传输预算和剩余容量；底层执行器从持有一致版本 KV 的节点中选择传输源。当前方案使用该启发式规则确定复制量，不再为 KV Manager 训练第二个策略。

后台复制不改变当前 Router 的动作定义，只改变下一轮可见的 KV 状态。系统状态转移可概括为：

$$
s_{k+1}
=H\left(
s_k,a_k,Y_k,U_{k+1},
\Delta\mathcal B_k,
\Phi_k^{\mathrm{place}}
\right),
$$

其中 $Y_k$ 和 $\Delta\mathcal B_k$ 是本轮真实输出长度及新增 KV blocks，$\Phi_k^{\mathrm{place}}$ 是下一请求到达前已完成并通过版本检查的后台复制结果。KV Manager 通过缩小 $\mathcal M_{k,j}$，同时减少 residual sync 的传输量和 residual recompute 的 token 数，从而降低未来的 $T^{\mathrm{state}}$；长期 Router 再判断当前恢复投入能否被后续多轮收益摊销。

## 3. 一个直接的例子

用户从节点 $A$ 移动到节点 $B$，完整 KV 仍在 $A$。假设两节点算力和显存充足、均不排队，之后还有 20 个请求从 $B$ 发出；继续在 $A$ 执行每轮增加 5 ms 请求转发时延，20 轮最多节省 100 ms。

下表中的 KV 恢复时延取节点 $B$ 上 residual sync 与 residual recompute 的较小值；若 $B$ 已有部分连续 prefix，recompute 只处理其后的缺失 suffix。

| KV 恢复时延 | 最优行为 | 原因 |
|---:|---|---|
| 1000 ms | 20 轮都发给 $A$ | $1000>20\times5$，整个 session 无法摊销 |
| 0 ms | 当前请求立即在 $B$ 执行 | $0<5$，单请求穷举与长期最优一致 |
| 40 ms | 提前恢复 KV，后续在 $B$ 执行 | $5<40<20\times5$，当前请求变慢，但 session 累计净节省 60 ms |

**长期路由只在第三种情况下产生单请求穷举无法得到的选择。**

## 4. 长期收益的有效成本区间

设：

- $F_k$：请求在远端 KV 节点执行时的请求发送与结果返回时延；
- $R_k$：将所需 KV 恢复到候选节点的一次性时延，即 residual sync 与 residual recompute 中较小的可行成本；
- $N_k$：恢复后的 KV 在候选节点可被复用的请求数。

仅考虑请求转发时，长期路由的有效区间为：

$$
F_k < R_k < N_kF_k.
$$

一般情况下，节点 $j$ 的非状态时延包括网络、排队、Prefill、Decode 和结果返回：

$$
C_k^{\mathrm{nonstate}}(j)
=T_k^{\mathrm{comm}}(j)+T_k^{\mathrm{queue}}(j)
+T_k^{\mathrm{prefill}}(j)+T_k^{\mathrm{decode}}(j)
+T_k^{\mathrm{return}}(j).
$$

设 $A$ 为完整 KV 所在节点，$B$ 为候选节点，则当前请求在 $B$ 执行可获得的非状态收益为：

$$
\Delta C_k^{\mathrm{current}}
=C_k^{\mathrm{nonstate}}(A)-C_k^{\mathrm{nonstate}}(B).
$$

未来请求的累计收益为：

$$
G_k=\mathbb E\left[
\sum_{h=0}^{N_k-1}\Delta C_{k+h}^{\mathrm{current}}
\right].
$$

长期路由的通用有效区间为：

$$
\Delta C_k^{\mathrm{current}}<R_k<G_k.
$$

$F_k$ 是 $\Delta C_k^{\mathrm{current}}$ 中的网络组成部分；当两节点没有排队和计算差异时，$\Delta C_k^{\mathrm{current}}=F_k$。

## 5. 模拟实验

### 5.1 实验配置

| 项目 | 配置 |
|---|---|
| 集群 | 3 台 A800T-A2；链路 100/100/25 Gbps |
| 轨迹 | 固定随机种子；120 s；136 个 session、2512 个请求 |
| Session 长度 | 截断对数正态分布：均值 40、标准差 10、范围 $[32,64]$；观察窗口内实际均值 18.47、P95 32 |
| 移动 | 5% 时长后启用；切换概率 20%；切换后至少驻留 16 轮 |
| 并发与平均轮间隔 | CodeLlama 高优 24/4 s、普通 96/8 s；Qwen-VL 16/5 s |
| 对比 | 单请求穷举（被动 KV）与单请求穷举 + 主动 KV placement |

Qwen-VL 在本节采用 16 并发，以降低突发排队对非状态收益的主导作用，集中观察 KV 恢复门槛及其可摊销区间；该设置用于机制分析，不替代 24 并发的验收口径。

为保持统计口径一致，主表只保留两种配置下均满足以下条件的相同请求：入口缺少完整 KV、远端存在完整 KV，且候选入口具有正非状态收益。CodeLlama34B 和 Qwen2-VL-7B 分别包含 118 和 47 个请求。

下表使用中位数估算量级。$F_k$ 为全部跨节点请求的网络转发时延，$R_k$ 和 $N_k$ 来自主表请求集合。

| 模型 | KV 机制 | $F_k$ P50 | $R_k$ P50 | 估算回本轮数 $R_k/F_k$ | $N_k$ P50 |
|---|---|---:|---:|---:|---:|
| CodeLlama34B | 被动 KV | 0.101 ms | 459.75 ms | 约 4550 | 5 |
| CodeLlama34B | 主动 KV | 0.102 ms | 135.97 ms | 约 1330 | 5 |
| Qwen2-VL-7B | 被动 KV | 0.291 ms | 419.74 ms | 约 1442 | 8 |
| Qwen2-VL-7B | 主动 KV | 0.291 ms | 45.02 ms | 约 155 | 8 |

**在 25/100 Gbps 链路上，仅靠节省请求转发时延无法摊销 KV 恢复；排队和计算差异必须进入长期收益模型。**

|---|---|---:|---:|---:|---:|
| CodeLlama34B | 被动 KV | 677.09 / **459.75** / 1467.26 | 20.49 / **0.40** / 87.92 | 6.17 / **5** / 14.15 | 2705.45 / **3200.52** / 4943.80 |

| Qwen2-VL-7B | 被动 KV | 412.67 / **419.74** / 659.84 | 45.49 / **0.29** / 316.22 | 7.94 / **8** / 15 | 1025.75 / **1258.74** / 2145.25 |
| Qwen2-VL-7B | 主动 KV | 60.88 / **45.02** / 165.02 | 36.88 / **0.29** / 270.41 | 7.94 / **8** / 15 | 108.86 / **100.32** / 250.38 |

回本轮数按请求分别计算后再汇总，因此不等于表中两个分位数直接相除。

为将请求划分到不同决策区间，实验使用当前非状态收益在剩余复用轮次内保持不变的有限窗口近似：

$$
G_k^{\mathrm{approx}}
=N_k\Delta C_k^{\mathrm{current}}.
$$

其中，$N_k$ 是当前请求及其后仍从候选入口到达、能够复用恢复后 KV 的请求数。三个区间分别表示：

- **当前请求即可摊销**：$R_k\leq\Delta C_k^{\mathrm{current}}$。一次状态恢复成本不超过当前请求节省的非状态时延，单请求穷举即可选择候选节点。
- **需要累计后续收益**：$\Delta C_k^{\mathrm{current}}<R_k<G_k^{\mathrm{approx}}$。当前一轮无法回本，但剩余多轮的累计收益可以覆盖恢复成本，需要 session 维度的长期判断。
- **剩余 session 无法摊销**：$R_k\geq G_k^{\mathrm{approx}}$。即使后续可复用请求全部获得相同收益，仍不足以覆盖恢复成本，应继续使用已有完整 KV 的节点。

| 模型 | KV 机制 | 当前请求即可摊销 | **需要累计后续收益** | 剩余 session 无法摊销 |
|---|---|---:|---:|---:|
| CodeLlama34B | 被动 KV | 0.85% | **8.47%** | 90.68% |
| CodeLlama34B | 主动 KV | 8.47% | **8.47%** | 83.05% |
| Qwen2-VL-7B | 被动 KV | 2.13% | **17.02%** | 80.85% |
| Qwen2-VL-7B | 主动 KV | 14.89% | **10.64%** | 74.47% |

### 5.4 只使用 recompute 的恢复结果

为观察 KV 恢复只能依赖计算时的成本，本实验固定 5.3 节的 47 个 Qwen2-VL-7B 请求及其系统状态，分别使用 sync 和 recompute 估计缺失 KV 的恢复时延。被动 KV 不启用 block-level 部分复用，recompute 需要重建完整历史 prefix；主动 KV 启用连续 block 管理后，recompute 只重建目标节点尚未持有的 suffix。该实验是同状态下的反事实比较，不重新改变请求路由轨迹。每个恢复时延单元格为“均值 / P50 / P95”，单位为 ms。

| KV 机制 | 强制恢复方式 | 恢复时延 $R_k$ | 回本轮数 P50 | 当前请求即可摊销 | **需要累计后续收益** | 剩余 session 无法摊销 |
|---|---|---:|---:|---:|---:|---:|
| 被动 KV | Sync | 412.67 / **419.74** / 659.84 | 1258.74 | 2.13% | **17.02%** | 80.85% |
| 被动 KV | Recompute | 2928.95 / **2655.16** / 6339.91 | 6376.44 | 0% | **4.26%** | 95.74% |
| 主动 KV | Sync | 60.88 / **45.02** / 165.02 | 100.32 | 14.89% | **10.64%** | 74.47% |
| 主动 KV | Recompute | 695.60 / **457.80** / 2220.77 | 1139.63 | 0% | **8.51%** | 91.49% |

结果表明：

- **当前条件下 sync 始终更快。** 47 个请求采用 sync/recompute 择优时均选择 sync，因此 5.2 和 5.3 节的 $R_k$ 实际等于 Sync 行。
- **主动 placement 同样能够降低 recompute 成本。** 目标节点已有更多连续 prefix 后，只需重算剩余 suffix，Recompute P50 从 2655.16 ms 降至 457.80 ms，下降 82.76%。
- **但只使用 recompute 仍难以进入可摊销区间。** 开启主动 KV 后，仍有 91.49% 的请求无法在剩余 session 内摊销，只有 8.51% 需要长期判断；这明显弱于 Sync 对应的 74.47% 和 10.64%。

因此，在当前 25/100 Gbps 链路与 Qwen2-VL-7B 计算配置下，recompute 是链路受限或同步不可用时的回退方案，而不是主要恢复方式。若链路带宽进一步下降、目标节点算力提高，或缺失 suffix 足够短，recompute 才可能优于 sync。

### 5.5 结论验证

- **状态恢复是主要门槛。** 被动 KV 下，CodeLlama34B 的 90.68% 和 Qwen2-VL-7B 的 80.85% 候选请求无法在剩余 session 内摊销恢复成本。
- **KV Manager 有效降低恢复门槛。** CodeLlama34B 的条件恢复成本逐请求降幅中位数为 77.52%；Qwen2-VL-7B 的条件恢复成本 P50 从 419.74 ms 降至 45.02 ms，无法摊销比例下降 6.38 个百分点。
- **长期路由只处理剩余的中间区间。** 主动 KV 后，仍有 8.47% 和 10.64% 的请求满足 $\Delta C_k^{\mathrm{current}}<R_k<G_k^{\mathrm{approx}}$。
- **恢复成本并非越低越能体现长期路由。** Qwen-VL 中部分请求由“无法摊销”直接转为“当前请求即可摊销”，使长期判断区间缩小；系统总时延仍然得到改善。
- **Recompute 不能替代当前高速链路上的 KV 同步。** 即使主动 placement 将 Qwen-VL 的 Recompute P50 降至 457.80 ms，仍显著高于 Sync 的 45.02 ms。

## 6. KV Manager 的作用

- **后台增量 placement**：提前复制稳定 KV prefix，减少请求关键路径上的恢复量。
- **Block 级残余恢复**：只同步或重算候选节点缺失的连续 blocks。
- **恢复方式选择**：当前模拟逐请求比较 residual sync 和 residual recompute，并采用预计完成时间更短的方式。
- **同步与重算编排**：进一步可将不同缺失部分分配给同步和重算流水并行恢复；该混合机制不计入当前实验结果。
- **KV block 拼接与目录合并**：将不同来源的 blocks 按版本和 token 区间组织为连续 prefix；该操作不融合 KV 数值，也不直接减少字节数。
- **KV vector merging、token 剪枝与量化**：进一步降低传输量、显存和带宽压力，但需要评估精度损失。

> **单请求穷举负责当前动作选择，KV Manager 降低候选节点的状态恢复门槛，长期 Router 则对仍处于中间成本区间的请求评估 session 后续收益。**

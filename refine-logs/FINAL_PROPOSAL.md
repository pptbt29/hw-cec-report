# Router 与 KV Manager 论文 Idea 评估

## 结论

**该方向的研究问题和系统范围足以支撑一篇完整论文，但当前方案的技术贡献还不足以支撑一篇强系统论文。**

问题不在于模块太少，而在于现有表述仍是两个较常见机制的拼接：

- Router 使用当前负载、链路和 KV 分布选择节点，进一步用 DQN 估计长期成本；
- KV Manager 按移动概率和 session 活跃度，成比例地复制连续 KV blocks。

上述组合能够构成完整系统，却尚未形成一个不可被现有工作替代的核心算法。继续增加 KV merge、token pruning、压缩或更多预测器不会自动增强论文，反而会使贡献失焦。

最值得发展的单篇论文主线是：

> **将移动边缘 LLM serving 建模为双时间尺度的状态就绪控制问题：后台 KV Manager 不追求尽可能多地复制 KV，而是用最小后台资源把候选节点推进到“足以改变在线路由选择”的就绪边界；在线 Router 再根据动态的残余恢复成本、排队和移动驻留时间决定当前请求的执行位置。**

这条主线把 Router 与 KV Manager 连接为同一个研究问题，同时仍允许二者在实现上保持低耦合。

## 1. 固定的问题边界

### 场景

- 多个边缘节点部署相同模型；
- 用户在一个多轮 session 内改变接入节点；
- 历史 KV 状态可能留在旧执行节点；
- 请求可以继续发往 KV 所在节点，也可以在其他节点恢复状态后执行；
- 后台链路可以在请求间隙预先复制部分 KV。

### 核心矛盾

在线路由同时面对两种相反的局部性：

- **用户局部性**：在靠近当前入口且排队较短的节点执行，可以减少通信和等待；
- **状态局部性**：在持有最新 KV 的节点执行，可以避免昂贵的状态恢复。

当前路由决定本轮新增 KV 在哪里增长，后台放置又改变未来节点的状态就绪程度，因此单轮动作会改变后续决策条件。

### 不纳入本篇主线

- 模型选择、模型并行和 prefill/decode 资源配比；
- KV 语义压缩、质量有损 token pruning；
- 跨模型 KV merge；
- 通用 KV 存储系统和复杂驱逐策略；
- 让一个 RL 策略直接输出每个 block 的传输动作。

这些内容可以作为复用的底层能力或后续工作，不能与主贡献并列。

## 2. 为什么当前 Idea 仍不够

### 2.1 Router 侧

“把状态、移动概率和输出长度输入 Double DQN”不是独立贡献。审稿人可以合理追问：

- 为什么单请求穷举、阈值策略或 MPC 不够？
- 长期策略在哪些状态区域会严格不同于单请求最优？
- DQN 学到的是 session 长期价值，还是成本估计误差？
- 当前执行节点改变未来 KV 分布的效应是否真实产生可测收益？

现有模拟中长期 Router 仍未稳定优于单请求穷举，说明“长期价值”目前是研究假设，还不是已验证机制。

### 2.2 KV Manager 侧

按移动概率和 session 活跃度复制固定比例 KV，是合理 baseline，但不是强论文算法：

- 转移概率 10% 不意味着最优复制比例是 10%；
- 它不知道还差多少 KV 才能使目标节点真正成为可选节点；
- 复制不足时不能改变 Router，复制过多时浪费带宽和显存；
- 多个 session 和多个候选节点竞争资源时，没有明确的资源优先级。

### 2.3 端到端证据

当前结果说明 KV Manager 能降低状态恢复成本并移动路由边界，但还存在以下证据缺口：

- 主要是仿真结果，尚未证明真实 KV 数据路径和并发资源竞争；
- workload 使用合成 session 和 oracle 输出/剩余长度，结论偏乐观；
- 主动 KV 的选中恢复事件集合发生变化，不能只用两组 P50 证明逐请求恢复成本的因果下降；
- 当前端到端增益主要来自单请求路由与 KV Manager，未隔离长期 Router 的增量收益。

## 3. 推荐的核心机制：面向路由边界的最小状态准备

设节点 $o$ 持有当前 session 的最新完整 KV，候选节点 $j$ 已持有长度为 $x$ 的连续 prefix。两处执行当前请求的预测关键路径成本分别为：

$$
C_o = T_o^{\mathrm{comm}} + T_o^{\mathrm{queue}} + T_o^{\mathrm{compute}},
$$

$$
C_j(x) = T_j^{\mathrm{comm}} + T_j^{\mathrm{queue}} + R_j(x) + T_j^{\mathrm{compute}},
$$

其中 $R_j(x)$ 是节点 $j$ 在已有 prefix 长度为 $x$ 时的残余状态恢复成本。随着连续 prefix 增长，$R_j(x)$ 单调不增。

定义使节点 $j$ 进入在线候选集合所需的最小准备量：

$$
x_j^* = \min \left\{x: C_j(x) \le C_o-\epsilon\right\},
$$

其中 $\epsilon$ 是对估计误差和系统抖动保留的安全裕量。KV Manager 的目标不再是最大化复制量，而是优先完成最有可能被未来请求使用、且距离 $x_j^*$ 最近的状态准备任务。

可以为 session $s$ 到节点 $j$ 的任务定义资源效率：

$$
I_{s,j} =
\frac{
p_{s,j}^{\mathrm{use}}
\left[C_{s,o}^{\mathrm{future}}-C_{s,j}^{\mathrm{future}}(x_j^*)\right]
}{
D_{s,j}(x_j^*-x_{s,j})
},
$$

其中：

- $p_{s,j}^{\mathrm{use}}$ 同时考虑移动到节点 $j$ 的概率、预计驻留时间和 session 继续概率；
- 分子表示达到就绪边界后可获得的未来服务收益；
- 分母表示从当前 prefix 推进到该边界所需的后台字节数。

后台调度按 $I_{s,j}$ 分配带宽，并在以下事件发生时滚动更新：请求完成、入口预测变化、队列变化、带宽变化和副本完成。该方法的关键不是精确预测一个遥远未来，而是持续计算“下一单位后台资源是否足以打开一个新的低成本路由动作”。

## 4. 在线 Router 应当怎样设计

Router 与 KV Manager 通过统一的 readiness profile 交互：

$$
\Phi_{s,j} = (x_{s,j}, R_{s,j}(x_{s,j}), v_{s,j}, M_j^{\mathrm{free}}),
$$

其中包含连续 prefix、残余恢复曲线、版本和容量可行性。Router 不需要知道 KV 是由预放置、同步还是重算获得，只使用当前真实可见的状态。

建议首先实现一个结构化的滚动策略，而不是直接把 DQN 作为主方法：

1. 对当前动作精确计算即时 E2E；
2. 对未来若干次入口和 session 存活事件做低分支 rollout；
3. rollout 内使用简单单请求最优策略；
4. 当前动作额外计入其对新增 KV 位置的影响；
5. 只执行第一步并在下一请求重新规划。

若离散状态仍然过大，再使用学习模型近似 rollout value。此时学习是降低在线计算开销的手段，而不是论文的新颖性来源。

## 5. 一篇论文的主贡献应如何组织

建议只保留一个主贡献和两个支撑贡献。

### 主贡献

**状态就绪边界驱动的双时间尺度控制。** 首次主张需经进一步检索后再使用。核心是按“改变路由选择所需的最小状态量”安排后台 KV，而非按命中率、概率或可用带宽盲目复制。

### 支撑贡献 1

**面向移动 session 的滚动路由。** 当前执行位置通过新增 KV 改变未来状态局部性，策略在移动驻留时间、队列差和残余恢复成本之间进行跨轮权衡。

### 支撑贡献 2

**真实系统原型与边界验证。** 在 KV block runtime 上实现异步预放置、暂停/续传、版本提交和残余恢复，并用真实测量验证理论就绪边界与实际路由切换点是否一致。

不要把以下项目单列为贡献：Double DQN、Markov mobility、输出长度预测器、block directory、break-even 公式、LRU/TTL、sync/recompute 枚举。

## 6. 与相邻工作的边界

| 相邻方向 | 已有能力 | 本文必须给出的额外内容 |
|---|---|---|
| Preble / DualMap | 在 prefix affinity 与负载均衡之间路由请求 | 处理同一移动 session 的状态增长，并主动改变未来状态分布 |
| Randomization Boosts KV Caching... | 联合 query routing 与有限缓存 eviction，并给出理论算法 | 从 eviction/命中率转向移动条件下的跨节点渐进复制与状态就绪边界 |
| CachedAttention / SYMPHONY | 提前加载或根据 advisory signal 预取 KV，隐藏慢存储访问 | 处理不确定目的节点、移动驻留时间和“准备到多少才改变路由”的问题 |
| Llumnix | 通过 live migration 支持动态重调度和负载均衡 | 在请求到达前分阶段准备 append-only session state，并控制误预测浪费 |
| Low-Latency Edge LLM Handover | handoff 时联合 KV 传输和 token prefill，降低恢复时延 | 在 handoff 前进行多阶段准备，并将准备进度与跨轮请求路由闭环 |
| AGENTSERVESIM | 仿真多轮 workload、session-aware routing 与 KV residency | 若以系统论文投稿，必须提供经过真实系统校准的机制结果，而非只增加一个仿真策略 |

因此，“移动性”本身不是足够差异；“Router + KV Manager”也不是足够差异。差异必须落到一个此前未被这些系统解决的控制问题上。

## 7. 必须补充的实验

### 7.1 最小因果矩阵

使用同一 workload 做 $2\times2$ 对照：

| | 被动 KV | 本文 KV Manager |
|---|---:|---:|
| 单请求 Router | A | B |
| 长期 Router | C | D |

必须分别证明：

- $B-A$：KV Manager 在固定 Router 下的独立收益；
- $D-B$：状态准备充分后长期 Router 的独立收益；
- $D-C$：固定长期 Router 时 KV Manager 的收益；
- 交互项 $(D-C)-(B-A)$：两者是否存在真正协同，而非简单相加。

### 7.2 边界验证

对每个候选动作记录：

- 当前已有 prefix 和到 $x_j^*$ 的字节差；
- 完整 KV 节点与候选节点的队列差；
- sync、residual recompute 和请求转发成本；
- 预测边界与实际 Router 切换点的误差；
- 达到边界后副本真正被使用的比例。

### 7.3 资源代价

至少报告：后台传输字节、峰值和平均带宽、目标 HBM/DRAM 占用、误预测字节、被取消任务、驱逐外部性，以及前台流量受干扰后的 TTFT。

### 7.4 真实性

- 真实或公开移动轨迹，而非只有固定 $0.8/0.1/0.1$ 转移矩阵；
- 真实多轮 chat、code agent、streaming VLM/VLA workload；
- 至少一个实际 KV runtime 原型；
- 仿真器必须用实机 prefill、decode、KV 传输和队列测量校准；
- 同时报告预测准确和预测错误情况下的性能。

## 8. Go / No-Go 标准

满足以下条件后，Idea 才进入可投稿状态：

1. 状态就绪边界算法相对固定比例、全量预复制和概率加权策略，显著降低无效字节，并保持或改善 TTFT；
2. 长期 Router 在相同 KV Manager 下稳定不劣于单请求 Router，并在中间恢复成本区间获得可重复增益；
3. $2\times2$ 实验显示正交增益或显著正交互项；
4. 至少在一类真实 workload 上证明移动预测和 session 驻留具有可利用结构；
5. 原型证明后台预放置不会因前台带宽/HBM 竞争抵消收益。

如果第 2 条无法成立，应删去“长期 Router”贡献，把论文收缩为 **mobility-aware, boundary-driven proactive KV preparation**；如果第 1 条无法超过简单固定比例策略，则 KV Manager 尚不足以成为论文核心。

## 9. 新颖性结论

基于截至 2026 年 7 月的初步检索：

- **“联合 Router 与 KV 管理”新颖性低。** 已有工作直接研究 routing、cache affinity、load balance 和 eviction 的联合关系。
- **“移动时同步或重算 KV”新颖性低至中。** 已有移动边缘 handover 工作联合 KV 传输与 prefill。
- **“根据预测提前预取 KV”新颖性中等偏低。** 已有 advisory/predictive prefetch 系统。
- **“以改变路由选择所需的最小 readiness 为后台复制目标，并与 session 状态增长形成闭环”目前具有中等偏高潜力。** 尚需扩大检索范围并精读全文，当前不能使用“首次”表述。

论文潜力取决于是否把最后一条做成真正的算法、原型和可验证边界，而不是换一个术语描述固定比例复制。

## 10. 最终建议

**继续按一篇论文推进，但立即停止横向增加功能。** 下一阶段只做三件事：

1. 将固定比例 KV placement 替换为“推进到路由竞争边界所需的最小复制量”；
2. 用结构化 rollout/MPC 证明长期 Router 的增量区间，再决定是否需要 DQN；
3. 用真实 KV runtime 校准并验证 $2\times2$ 因果矩阵。

推荐暂定标题：

> **Prepare Just Enough State: Mobility-Aware KV Readiness and Long-Horizon Routing for Edge LLM Sessions**

一句话主张：

> 系统不让 KV 无条件跟随用户迁移，而是只投入足以使候选节点跨过路由竞争边界的后台资源，再由 session 级 Router 判断何时利用该节点，从而以较少的复制浪费获得更早的负载均衡和移动切换能力。

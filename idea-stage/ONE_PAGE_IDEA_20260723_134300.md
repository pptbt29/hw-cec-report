# One-Page Paper Idea v0.1

**暂定标题**：*Prepare to Route, Not to Cache: Budgeted KV Readiness for Stateful Edge Inference*

**若 mobility 因果实验通过，标题再改为**：*Prepare to Route, Not to Cache: Budgeted KV Readiness for Mobile Multimodal Sessions*

**当前裁决**：**Conditional Go**。已经被现有结果支持的问题是“缺失 session state 会阻止 Router 使用短队列节点，而无差别预放置会浪费大量带宽与 HBM”；尚未被支持的问题是“收益由用户移动产生”。因此，第一版论文不把 mobility、VLM、长期 Router、SafeRL 或 Lyapunov 当作既定贡献。

> **一句话主张**：在多 session 竞争有限后台带宽和 HBM 时，不按目的地概率摊薄复制 KV，而是优先完成少数能够在 deadline 前使候选节点满足 SLO、或进一步改变当前路由选择的最小 state deficit。

## 1. One-page summary

### 1.1 哪个问题确实存在

现有五随机种子实验给出一个一致但仍限于合成环境的均值趋势：随着并发从 8 增至 48，Greedy+KV 相对相同 Greedy Router 将平均端到端时延降低约 1.0%--7.7%，主要变化是平均排队时间下降；但每 120 秒同时产生约 35.7--169.6 GB 的后台复制。在并发 36 时，“proactive-only”平均复制约 147 GB，却没有统计上明确的端到端收益。这个结果说明“复制了多少”不是价值，“复制后是否新增一个可用执行节点”才可能是价值。

它目前不能证明 mobility 重要。本轮单种子因果诊断中，mobility probability 为 0 时 Greedy+KV 仍比 Greedy 低 3.12%，mobility probability 为 0.7 时仅低 1.88%，收益不随移动率单调增加；扩大多模态 payload 也没有带来单调收益。当前模拟器还读取真实剩余轮数、未让前台转发流量真实争用链路、使用无限 KV capacity，因此这些结果只能用于筛选问题，不能作为论文结果。

从第一性原理看，令 $F$ 为把新请求转发到旧 state owner 的每轮增量通信成本，$\Delta Q$ 为旧节点相对候选节点的队列劣势，$R$ 为准备 state 的一次性成本，则最简单的摊销边界为：

$$
H^*=\frac{R}{F+\Delta Q}.
$$

只有预计剩余交互轮数 $H>H^*$ 时，准备 state 才可能优于继续转发。这里的 $F$ 只应计算“因远端执行而新增的 inter-edge 路径”，不能把所有策略共同承担的 UE 上行成本算成 mobility 收益。当前 text 和 VLM 仿真中，$\Delta Q$ 往往比 $F$ 更能打开准备区域；OpenVLA 的 state/payload 比过高且队列差过小，约 96.7 GB 的复制没有改善平均时延，因此 VLA 暂时是 No-Go。

### 1.2 要研究的最小问题

系统面对多个增长中的 session。对于每个 session--node pair，后台 Manager 只知道下一轮是否发生、何时发生、从哪里进入、输入输出长度和 KV 增长量的分布，而不知道真实未来。Manager 必须在共享 NIC、PCIe 和 HBM 预算下决定：哪些有效连续 KV prefix 应该被准备到哪个节点、准备多少、何时停止或驱逐。在线 Router 只根据当前真实队列、链路和 state readiness 选节点。

令 $x$ 是节点 $j$ 已持有的 session $s$ 的最新有效连续 prefix，$T_{s,j}(x,t)$ 是包含增量通信、排队、残余恢复和计算的请求时延。必须分开定义两个作用不同的 boundary。

$$
x^{SLO}_{s,j}(t)=\min\{x\mid P(T_{s,j}(x,t)\le D_s)\ge 1-\epsilon\}.
$$

$$
x^{win}_{s,j}(t)=\min\{x\mid E[T_{s,j}(x,t)]\le T_s^{best}(t)-\delta\}.
$$

$x^{SLO}_{s,j}$ 让节点获得服务资格，即使它暂时不是最快节点，也能在负载上升时增加可用并行容量；$x^{win}_{s,j}$ 才表示它已经足以改变当前 latency-minimizing route。把两者合并会错误排除“满足 SLO 但略慢于当前 best”的容量。Manager 调度的对象不是整个 KV，也不是 cache-hit probability，而是对应的 SLO deficit 和 win deficit。它先排除无法在预测 deadline 前完成或即使完成也不会改善容量的任务，再把资源集中给少数高价值 deficit，完成一个后重新估值。append-only state 的旧副本只作为可继续补齐的有效 prefix，不另立一套算法。Router 则降级为 boundary consumer；除非短窗口 MPC 在相同 Manager 下稳定优于 Greedy，否则不引入长期 DQN。

主指标 SLO-goodput 必须按固定 offered trace 定义。令 $R_o$ 为测量窗口内所有 offered requests，$I_r=1$ 仅当请求 $r$ 被完成且时延不超过 $D_r$，否则 $I_r=0$，则：

$$
G=\frac{\sum_{r\in R_o} I_r}{T_m}.
$$

其中 $T_m$ 是测量时长；拒绝、丢弃和超时请求全部计为 0。所有方法使用相同的 offered trace 与 admission rule，并同时报告 drop ratio、不同 session-size/tenant class 的 SLO 达成率和 HBM-time，防止通过饿死困难请求提高 goodput。

实际只建设四个部件：

1. 测量不同有效 prefix 下的 transfer/recompute/queue latency，形成在线 readiness curve；
2. 根据保守的下一次使用时间和目的地分布，计算每个 session--node pair 的 deficit 与失效 deadline；
3. 在有限后台带宽和 HBM 下集中完成最小有价值 deficit，并随系统变化抢占或取消任务；
4. 让简单 Router 消费真实 readiness；未 qualified 的节点继续走 sticky、reactive restore 或 recompute fallback。

### 1.3 唯一可证伪的核心主张

> 在多 session 竞争有限后台字节和副本内存、下一请求目的地和时间不确定时，以 routeability deficit 为单位集中完成 state preparation，能在相同后台带宽与 HBM 预算下，比 reactive restore、top-1 full prefetch、概率比例预取、marginal-utility prefetch 和机制完整的 SYMPHONY scheduler 获得更高的 SLO-goodput。

这条主张只有在以下现象同时成立时才有论文价值：

1. sub-threshold progress 对 SLO-goodput 的价值明显弱于跨过 boundary，而不是所有字节都具有平滑、等比例的边际收益；
2. 多 session 资源竞争中，“平均摊薄后全部来不及”与“集中后部分获得路由资格”形成可复现实验差异；
3. 预测 boundary 在准备完成前不会因队列变化而频繁失效，或保守估计能够控制 false qualification；
4. 在固定 bytes/HBM 下，本文方法超过最强的非 Oracle baseline，而不只是比当前 naive policy 更好。

其中 [SYMPHONY](https://www.usenix.org/conference/nsdi26/presentation/agarwal) 是最危险的相邻工作：baseline 必须忠实包含错误 advisory、多个潜在 downstream、优先级和 partial/layer-wise loading；若它与本文方法处于同一 Pareto 前沿，则差异不足。如果上述条件不成立，routeability 只是 break-even 的重新命名，应停止算法论文主线，转向“何时 KV 不应跟随 session”的测量与相图论文。

写作约束采用公开课程材料 [Choosing a Title and Writing the Abstract](https://chaosonglab.github.io/files/course_materials/sci_writing/lecture7_abstract.pdf) 中的规则：单段、自包含、不引用图表、不放 citation、不使用未解释缩写；`[S1]`--`[S10]` 只用于核对句数，投稿时删除。

> [S1] Stateful language and vision-language inference is increasingly placed on edge accelerators to reduce access latency. [S2] Multi-turn sessions accumulate a large key-value cache that can remain on one accelerator after the user's ingress point or the least-loaded accelerator changes. [S3] We focus on the regime in which state recovery changes the set of nodes able to satisfy a latency objective, while treating mobility as a candidate signal rather than an assumed source of benefit. [S4] Preparing more state is not necessarily more useful because partial replicas may consume shared resources without qualifying any node before the next request. [S5] We present Prepare-to-Route, a controller for multiple uncertain sessions that treats background key-value preparation as scarce-resource allocation rather than cache-hit maximization. [S6] For each session-node pair, it estimates the smallest contiguous state deficits needed to meet a first-token latency target and, separately, to beat the best current route. [S7] A deadline-aware scheduler concentrates network bandwidth and accelerator memory on deficits likely to cross one of these boundaries before use instead of spreading partial replicas across all likely destinations. [S8] A simple online router then chooses from currently qualified nodes, while exact future requests, destinations, input and output lengths, and session lifetimes are reserved for an oracle baseline. [S9] [Final-result placeholder] On a multi-node prototype and trace-driven replay, Prepare-to-Route increases the number of offered requests meeting the latency objective per second by X percent and reduces 99th-percentile time to first token by Y percent at the same background-byte and memory budgets, while reducing unused prepared bytes by Z percent against the strongest non-oracle baseline. [S10] These results would show that the useful primitive is not making the cache follow every mobile user, but completing the smallest state preparations that create new service capacity.

## 3. Introduction draft：七段逻辑

### P1：先定义真正的系统矛盾

**Stateful edge inference creates a three-way locality conflict among fresh input, reusable state, and spare compute.** 移动用户的新文本、图像或视频从当前入口到达，长 session 的历史 KV 留在过去执行节点，而短队列 GPU 可能位于第三个节点。系统因而必须在“把新数据送到 state”“把 state 准备到数据附近”和“等待本地计算”之间选择。该段只建立 data--state--compute 三重局部性，不预设移动 state 一定有利。

### P2：主动否定“移动即迁移”

**User mobility does not by itself make KV migration necessary.** 对 text request，高速 edge fabric 上的增量转发成本可能只有亚毫秒，而恢复或迁移 KV 需要几十至数百毫秒；即使是 VLM，只有真实 inter-edge media path 足够重，且不是所有策略共同承担的无线接入成本，mobility 才会改变最优动作。当前诊断实验中，去掉 mobility 后 KV warming 的收益仍然存在，因此本文把 mobility 视为待验证的结构化信号，而不是问题成立的公理。

### P3：用现有数据指出资源效率问题

**The observed failure is not insufficient prefetching but prefetching that never creates a usable route.** 在并发 36 的五种子合成实验中，proactive-only 平均传输约 147 GB/120 s，却没有统计上明确的端到端改进；相反，能够降低 residual recovery 的完整 Manager 主要通过缩短排队获得收益。这说明 cache bytes、hit ratio 或预测目的地概率都不是充分目标，真正需要解释的是准备进度何时会让短队列节点进入 Router 的可选集合。

### P4：准确划定与已有工作的边界

**Existing systems already cover routing, migration, and predictive prefetch, so combining them is not the research gap.** [Preble](https://proceedings.iclr.cc/paper_files/paper/2025/hash/5bc342f48de8264779952fac378f96dc-Abstract-Conference.html) 和 [Mooncake](https://www.usenix.org/conference/fast25/presentation/qin) 已联合考虑 cache locality、负载和恢复成本；[SYMPHONY](https://www.usenix.org/conference/nsdi26/presentation/agarwal) 已使用不可靠 advisory 做 KV prefetch 与调度；[Low-Latency Edge LLM Handover](https://arxiv.org/abs/2603.28018) 已在移动 handover 中联合选择 KV transfer 与 prefill。本文可能存在的窄缺口不是“首次联合”，而是：在多 session 共享资源下，以“完成多少 state 才新增一个满足 SLO 的执行节点、或一个能改变当前选择的竞争节点”为资源分配单位。

### P5：把未知未来和唯一目标写清楚

**The resulting problem is an online deadline-allocation problem under uncertain session futures.** 可部署策略只能从历史交互估计 continuation probability、top-k destination distribution、dwell-time distribution、输入输出长度分布和 state growth quantile；真实剩余请求数、真实未来入口和真实输出长度只允许出现在 Oracle 上界中。主目标固定为给定网络与 HBM 预算下的 SLO-goodput，P99 TTFT、wasted bytes 和 memory footprint 用作结果与约束，不使用难以解释的任意加权总成本。

### P6：用一个控制原语贯穿设计

**Prepare-to-Route makes the routeability deficit the interface between the background Manager and the online Router.** Manager 为每个 session--node pair 估计带不确定性区间的 readiness curve，并分别计算 $x^{SLO}_{s,j}$ 和 $x^{win}_{s,j}$，把有限资源集中给能在 deadline 前完成且能增加可行容量或改变当前 route 的 deficit；Router 只消费当前真实 readiness 和 queue estimate，执行 Greedy 或短窗口 MPC。这样，预测器、KV directory、block transfer、recompute 和 eviction 都是实现组件，不再被包装成平行贡献。

### P7：最后只提出三项有证据路径的贡献

**The paper will make three claims, each tied to a falsifiable experiment.** 第一，真实 runtime characterization 证明 routeability boundary 是否稳定存在，并给出 forward、retain、partial-prepare、full-prepare 与 recompute 的相图；第二，multi-session deficit scheduler 在固定 bytes/HBM 下提高 SLO-goodput，若不能超过 probability/marginal baselines 则该 claim 被否证；第三，因果实验判断 mobility 和 VLM data locality 是否提供独立信息，只有该实验通过后才把“mobile multimodal”写进标题和贡献。

## 5. 实验计划

### 5.1 先做最小否证实验，再建设完整系统

**Gate A -- VLM state 语义，预计 2--3 天、少于 8 GPU-hours。** 在真实 VLM runtime 中验证多轮图像上下文的 prefix KV 能否跨轮精确复用，比较 full prefill 与 reuse 的输出一致性、TTFT 和实际 state size。若动态视觉 token、位置编码或 prompt formatting 破坏 prefix 语义，则 VLM 从主场景移除；VLA 不进入本 gate。

**Gate B -- routeability 是否超过代数 break-even，预计 3--5 天、少于 20 GPU-hours。** 用两个真实 GPU 节点扫描 prefix fraction、queue gap、state size、inter-edge bandwidth/RTT 和固定 input representation，分别测量预测 $x^{SLO}$ 与实际 SLO qualification、预测 $x^{win}$ 与实际 Router 切换点，以及 false qualification 和 boundary lifetime。若 partial progress 的收益平滑到 marginal-utility baseline 已能取得同一 Pareto，停止 routeability 算法。

**Gate C -- 多 session 集中资源是否有效。** 离散事件 replay 只用于快速筛选 16--128 个 session 下的候选算法；最终通过条件必须在真实争用原型上验证。前台 forwarding、reactive recovery 和后台 preparation 真实共享 NIC、PCIe 与 HBM，所有方法使用相同 offered trace、admission rule、总 background bytes、HBM-time 和 offered load。在至少两个非极端负载区间，相对最强非 Oracle baseline 的 SLO-goodput 提升需达到预注册的 10%，95% paired confidence interval 不跨 0，且不能以更高 drop ratio 或明显更差的 class/session fairness 换取。

**Gate D -- mobility 是否具有独立因果价值。** 固定 arrival、queue、payload、session continuation 和随机种子，只替换原始 mobility、destination-shuffled、timing-shuffled、mobility=0 和 generic session-return predictor。若 mobility-aware signal 相对 generic predictor 的额外收益不足 5% 或 95% paired confidence interval 跨 0，则从标题、Abstract 和贡献中删除 mobility；VLM 只保留为 workload。

### 5.2 完整评测设置

- **原型**：3--8 个真实或受控共享的 GPU inference workers；使用现成 block KV data plane，实现本文的 readiness telemetry、background throttling 和 scheduler，而不重新发明存储层。
- **模型**：通过 Gate A 的长 session VLM 为候选主 workload；长对话 text model 为必要控制组；OpenVLA/VLA 当前排除。
- **网络**：实验室 25/100 Gbps，加受真实 trace 驱动的受限 backhaul、RTT、突发拥塞和前后台共享；前台 request forwarding、前台恢复和后台准备必须争用同一实际资源模型。
- **会话与移动**：公开多轮会话 trace 加至少一组公开 mobility/handover trace；合成模型只用于控制变量，不充当唯一证据。
- **在线信息**：continuation 用 survival/hazard estimate，目的地和驻留时间用 calibrated distribution，输入输出长度用在线 quantile；真实未来只用于 Oracle。
- **资源压力**：有限 HBM、异构节点、metadata delay、session state 增长、foreground priority 和版本失效全部纳入。
- **重复性**：固定成对 trace 和随机种子，报告均值、P50/P95/P99、95% confidence interval，并公开 workload generator、参数与所有负结果。

### 5.3 Baselines

1. state-sticky forwarding；
2. load-only Router + reactive recompute/restore；
3. cache/load-aware Greedy + reactive restore；
4. top-1 full prefetch；
5. probability-proportional multi-destination prefetch；
6. marginal-utility/water-filling partial prefetch；
7. 机制完整的 SYMPHONY scheduler：包含 spurious advisory、多个 downstream targets、优先级以及 partial/layer-wise loading；
8. 本文 deficit scheduler + 同一个 Greedy Router；
9. 本文 Manager + 短窗口 MPC Router，仅用于检验 Router 是否还有独立增益；
10. clairvoyant Oracle，仅作上界。

### 5.4 Research questions 与指标

| RQ | 要回答的问题 | 主要指标 |
|---|---|---|
| RQ1 | 真实系统中是否存在稳定、可预测的 routeability boundary？ | boundary error、false qualification、boundary lifetime |
| RQ2 | deficit scheduling 是否在固定资源下优于最强 baseline？ | SLO-goodput、P99 TTFT、SLO violation、drop ratio、per-class fairness |
| RQ3 | 节省是否来自更少浪费而非更多复制？ | bytes per SLO saved、unused bytes、HBM-time、NIC/PCIe interference |

| RQ5 | 未知未来和系统波动下是否仍有效？ | destination/continuation error、queue volatility、metadata delay |
| RQ6 | 控制器是否可部署？ | decision latency、telemetry traffic、scale with sessions/nodes |

### 5.5 必要消融

- 去掉 boundary，只按 destination probability 分配；
- 去掉集中完成，改为按概率摊薄；
- 去掉 stale-but-valid prefix，只允许 binary full cache；
- 用真实在线 estimate 替换 Oracle 后的性能差；
- 同一 Manager 下 Greedy 与短窗口 MPC 的配对比较；
- text、VLM 及不同 input representation 只作为 workload axis，不把 representation selection 扩成第二个优化问题；
- mobility 原序列、shuffle 和 no-mobility 的因果比较。

## 6. Claim--evidence map

| Claim | 当前状态 | 现有证据 | 还缺什么 |
|---|---|---|---|
| 缺失 KV 会阻止短队列节点参与负载均衡 | 初步支持 | 并发 8--48 的五种子实验中 queue 和 E2E 同步下降 | 真实 runtime 与有限资源复现 |
| naive proactive preparation 资源效率低 | 初步支持 | 并发 36 时 proactive-only 约 147 GB/120 s，E2E 无明确改善 | 排除模拟器实现偏差，测量 foreground interference |
| routeability deficit scheduler 优于 probability/marginal scheduling | 未验证 | 只有定义和解析反例 | Gate B、Gate C 与 Pareto 结果 |
| mobility 是收益的必要来源 | 当前证据反对 | mobility=0 仍有收益，且收益不随 mobility 单调变化 | Gate D；失败则删除 mobility claim |
| VLM 会让 mobility 变成一阶成本 | 未验证 | payload sweep 非单调，当前 payload 为人为设定 | 真实 media path、prefix 语义、链路竞争和 trace |
| VLA 是合适 workload | 当前否定 | 约 96.7 GB 复制无平均 E2E 收益，state 语义也不匹配 | 另立 VLA caching/control paper，不在本文解决 |

## 7. 明确不做什么

- **不把长期 DQN 当贡献**：现有 Long-term Router 没有稳定超过 Greedy；先用短窗口 MPC 验证是否存在长期价值。
- **不使用 SafeRL 包装 SLO**：action mask、保守 qualification 和 fallback 更直接；constrained RL 也不能自动保证 P99。
- **不把 Lyapunov 当新颖性**：只有运营者确实给出长期平均带宽、能耗或租户公平预算时，才可把 virtual queue 作为标准求解器。
- **不做 VLA**：当前 workload 不满足持续增长、可复用 session KV 的关键假设。
- **不同时优化 input representation**：raw frame、compressed image、feature 和 visual token 先作为测量轴；联合 representation selection 会把问题扩成另一篇 split-inference paper。
- **不声称 formal certificate**：在 boundary coverage 和 false-positive rate 未经真实校准前，正文使用 readiness boundary 或 qualified node；只有给出可验证 coverage 后才使用 certified。
- **不读取 Oracle future**：真实剩余轮数、真实目的地、真实输入输出长度只用于上界。

## 8. Go / No-Go 与备选论文

**继续系统算法论文的 Go 条件**：

1. Gate A 证明真实 long-session runtime 存在可迁移、可部分复用的有效 state；
2. Gate B/C 证明 boundary-aware concentration 在 bytes--HBM--SLO-goodput Pareto 上超过 top-1、probability、marginal 和 advisory baselines；
3. 在线估计不依赖真实未来，且预测误差下收益仍存在；
4. strongest non-Oracle baseline 上的主要改进达到预注册工程阈值并有成对置信区间。

**立即 No-Go 或 pivot 的条件**：

1. 简单 full prefetch 或 marginal-utility 已位于同一 Pareto 前沿；
2. boundary 在准备完成前频繁失效，导致集中调度反而浪费；
3. 多 session 下没有“摊薄全失败、集中部分成功”的区域；
4. 真实 KV runtime 中 partial prefix 无法正确复用；
5. mobility ablation 失败但文章仍试图以 mobility 为主贡献。

若算法 gate 失败但真实测量得到稳定相图，备选论文改为：

> *Leave the Cache Behind: When Stateful Edge Inference Should Forward, Recompute, or Prepare KV*

该 pivot 的贡献将是跨模型、网络、负载和 session 长度的实测 phase diagram，以及“移动不等于迁移”的反直觉系统结论，而不是新调度算法。

## 9. 当前最合理的执行顺序

1. 先完成 Gate A/B，不改大系统；
2. Gate B 通过后实现多 session deficit scheduler，并优先比较 marginal-utility 与机制完整的 SYMPHONY baseline；
3. Gate C 通过后再补真实 mobility/VLM trace 和 Gate D；
4. Gate D 通过才把 mobile multimodal 写进标题；
5. 最后才判断是否需要 MPC、Lyapunov solver 或 formal coverage，默认都不需要。
